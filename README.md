# Bank Account Micro Project

Небольшой учебный Python-проект для демонстрации основных принципов ООП: абстракции, наследования, инкапсуляции, `Enum`, пользовательских исключений и валидации данных.

## Возможности

* Абстрактный класс `AbstractAccount`
* Конкретный класс `BankAccount`
* Автоматическая генерация короткого UUID
* Статусы счёта:

  * `ACTIVE`
  * `FROZEN`
  * `CLOSED`
* Поддерживаемые валюты:

  * `RUB`
  * `USD`
  * `EUR`
  * `KZT`
  * `CNY`
* Пополнение счёта через `deposit()`
* Снятие средств через `withdraw()`
* Получение информации через `get_account_info()`
* Валидация входных данных
* Защита от отрицательных и нулевых сумм
* Проверка достаточности средств
* Запрет операций для замороженных и закрытых счетов
* Собственные классы исключений
* Человекочитаемое строковое представление через `__str__()`

## Основные классы

### AbstractAccount

Абстрактный базовый класс для банковских счетов.

Содержит:

* `account_id` — уникальный идентификатор;
* `personal_info` — данные владельца;
* `_account_balance` — баланс счёта;
* `account_status` — текущий статус.

Определяет следующие абстрактные методы:

```python
deposit(amount)
withdraw(amount)
get_account_info()
```

### BankAccount

Конкретная реализация банковского счёта.

Если `account_id` не передан при создании объекта, автоматически генерируется короткий UUID.

Пример:

```python
account = BankAccount(
    personal_info="Alexey",
    account_balance=10000,
    currency=Currency.RUB
)
```

## Status

Статус счёта представлен через `Enum`:

```python
class Status(Enum):
    ACTIVE = "active"
    CLOSED = "closed"
    FROZEN = "frozen"
```

Правила операций:

| Статус   | Deposit  | Withdraw |
| -------- | -------- | -------- |
| `ACTIVE` | Разрешён | Разрешён |
| `FROZEN` | Запрещён | Запрещён |
| `CLOSED` | Запрещён | Запрещён |

## Currency

Поддерживаются следующие валюты:

```python
RUB
USD
EUR
KZT
CNY
```

## Исключения

Проект содержит четыре собственных исключения:

| Исключение               | Назначение                               |
| ------------------------ | ---------------------------------------- |
| `AccountFrozenError`     | Попытка операции над замороженным счётом |
| `AccountClosedError`     | Попытка операции над закрытым счётом     |
| `InvalidOperationError`  | Некорректные входные данные или операция |
| `InsufficientFundsError` | Недостаточно средств для снятия          |

## Deposit

Перед пополнением выполняются проверки:

1. Счёт не должен быть заморожен.
2. Счёт не должен быть закрыт.
3. `amount` должен быть числом.
4. `amount` должен быть больше `0`.

После успешной проверки:

```text
balance = balance + amount
```

## Withdraw

Перед снятием выполняются проверки:

1. Счёт не должен быть заморожен.
2. Счёт не должен быть закрыт.
3. `amount` должен быть числом.
4. `amount` должен быть больше `0`.
5. На счёте должно быть достаточно средств.

После успешной проверки:

```text
balance = balance - amount
```

## Валидация

При создании счёта проверяются:

* корректность `account_id`;
* корректность данных владельца;
* корректность начального баланса;
* отсутствие отрицательного баланса;
* корректность `Status`;
* корректность `Currency`.

Для денежных операций проверяется:

```text
amount > 0
```

и тип значения.

## Строковое представление

Метод `__str__()` выводит:

* тип счёта;
* клиента;
* последние 4 символа ID;
* статус;
* баланс;
* валюту.

Пример:

```text
BankAccount | Client: Alexey | Account: ****a123 | Status: active | Balance: 10000 RUB
```

Полный идентификатор счёта не отображается.

### `algorithm.md`

# Algorithm

## 1. Создание счёта

При создании `BankAccount` выполняется следующая последовательность:

```text
START
  |
  v
Передан account_id?
  |
  +-- NO --> Сгенерировать UUID
  |           и взять короткую часть
  |
  +-- YES -> Использовать переданный ID
  |
  v
Проверить account_id
  |
  v
Проверить personal_info
  |
  v
Проверить account_balance
  |
  +-- balance < 0 --> InvalidOperationError
  |
  v
Проверить account_status
  |
  v
Проверить currency
  |
  v
Создать объект BankAccount
  |
  v
END
````

## 2. Deposit

Алгоритм пополнения счёта:

```text
START
  |
  v
Проверить статус
  |
  +-- FROZEN --> AccountFrozenError
  |
  +-- CLOSED --> AccountClosedError
  |
  +-- ACTIVE --> продолжить
  |
  v
Проверить тип amount
  |
  +-- некорректный --> InvalidOperationError
  |
  v
amount > 0?
  |
  +-- NO --> InvalidOperationError
  |
  +-- YES
  |
  v
balance = balance + amount
  |
  v
END
```

Формула:

```text
new_balance = current_balance + amount
```

## 3. Withdraw

Алгоритм снятия средств:

```text
START
  |
  v
Проверить статус
  |
  +-- FROZEN --> AccountFrozenError
  |
  +-- CLOSED --> AccountClosedError
  |
  +-- ACTIVE --> продолжить
  |
  v
Проверить тип amount
  |
  +-- некорректный --> InvalidOperationError
  |
  v
amount > 0?
  |
  +-- NO --> InvalidOperationError
  |
  +-- YES
  |
  v
balance >= amount?
  |
  +-- NO --> InsufficientFundsError
  |
  +-- YES
  |
  v
balance = balance - amount
  |
  v
END
```

Формула:

```text
new_balance = current_balance - amount
```

## 4. Проверка статуса

Для денежных операций используется единое правило:

```text
ACTIVE
  |
  +--> операция разрешена

FROZEN
  |
  +--> AccountFrozenError

CLOSED
  |
  +--> AccountClosedError
```

Проверка статуса вынесена в отдельный метод `_check_operation_allowed()`.

Это позволяет избежать дублирования одинаковой логики в `deposit()` и `withdraw()`.

## 5. Валидация суммы

Метод `_validate_amount()` проверяет:

```text
amount должен быть int или float
amount должен быть > 0
```

Примеры:

```text
100       -> OK
100.50    -> OK
0         -> InvalidOperationError
-100      -> InvalidOperationError
"100"     -> InvalidOperationError
None      -> InvalidOperationError
```

## 6. Проверка баланса

Перед снятием денег выполняется:

```text
current_balance >= amount
```

Если условие не выполняется:

```text
InsufficientFundsError
```

Баланс при этом не изменяется.

## 7. Получение информации

Метод:

```python
get_account_info()
```

возвращает словарь:

```text
{
    account_id,
    personal_info,
    balance,
    status,
    currency
}
```

Таким образом, внешний код может получить структурированную информацию о счёте.

## 8. Строковое представление

Метод `__str__()` формирует краткое описание:

```text
BankAccount |
Client: <client> |
Account: ****<last 4 digits> |
Status: <status> |
Balance: <balance> <currency>
```

Для номера счёта используются только последние четыре символа.

## 11. Сложность алгоритмов

Основные операции выполняются за постоянное время:

| Операция             | Временная сложность | Дополнительная память |
| -------------------- | ------------------: | --------------------: |
| Создание счёта       |              `O(1)` |                `O(1)` |
| `deposit()`          |              `O(1)` |                `O(1)` |
| `withdraw()`         |              `O(1)` |                `O(1)` |
| `get_account_info()` |              `O(1)` |                `O(1)` |
| `__str__()`          |              `O(1)` |                `O(1)` |

Алгоритмы не используют циклы или структуры данных, размер которых зависит от количества счетов, поэтому основные операции имеют постоянную сложность.
