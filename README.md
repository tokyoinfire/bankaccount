# Bank Account Micro Project

Учебный Python-проект для демонстрации принципов ООП и разработки небольшого банковского приложения: абстракции, наследования, инкапсуляции, `Enum`, пользовательских исключений, валидации, очередей, транзакций, аудита, анализа рисков и формирования отчётов.

## Возможности

- Абстрактный класс `AbstractAccount`
- `BankAccount` — стандартный банковский счёт
- `SavingsAccount` — накопительный счёт с минимальным балансом и процентами
- `PremiumAccount` — премиальный счёт с комиссией и ограничением минимального остатка
- `InvestmentAccount` — счёт с инвестиционным портфелем
- Автоматическая генерация UUID для счетов и транзакций
- Поддержка статусов счетов и клиентов
- Поддержка нескольких валют
- Пополнение и снятие средств
- Инвестиции в `STOCKS`, `BONDS` и `ETF`
- Расчёт распределения инвестиционного портфеля
- Расчёт ожидаемого годового роста портфеля
- Управление клиентами и их счетами
- Аутентификация клиентов
- Блокировка после трёх неудачных попыток входа
- Проверка принадлежности счёта клиенту
- Ограничение финансовых операций в ночное время
- Транзакции с жизненным циклом и статусами
- Очередь транзакций на базе `heapq`
- Приоритеты и отложенное выполнение транзакций
- Обработка переводов, пополнений и снятий
- Комиссии и конвертация валют
- Повторные попытки обработки транзакций
- Защита от повторного применения завершённых транзакций
- Аудит операций
- Анализ риска транзакций и клиентов
- Формирование клиентских и банковских отчётов
- Статистика транзакций
- Экспорт отчётов в JSON и CSV
- Сохранение графиков через `matplotlib`

## Основные классы

### `AbstractAccount`

Абстрактный базовый класс для банковских счетов.

Определяет общий интерфейс:

```python
deposit(amount)
withdraw(amount)
get_account_info()
```

Также предоставляет свойство `total_balance`, которое используется для расчёта общей стоимости активов.

Для обычных счетов `total_balance` равен свободному балансу. `InvestmentAccount` переопределяет это свойство и включает стоимость инвестиционного портфеля.

### `BankAccount`

Стандартный банковский счёт.

Основные свойства:

- `account_id` — уникальный идентификатор;
- `personal_info` — информация о владельце;
- `_account_balance` — баланс;
- `account_status` — статус счёта;
- `currency` — валюта;
- `account_type` — тип счёта.

Если `account_id` не передан, создаётся UUID.

Пример:

```python
account = BankAccount(
    personal_info="Alexey",
    account_balance=10000,
    currency=Currency.RUB,
)
```

### `SavingsAccount`

Накопительный счёт.

Дополнительно поддерживает:

- минимальный допустимый баланс;
- ежемесячную процентную ставку;
- начисление процентов.

Если после снятия средств баланс окажется ниже минимального, возникает `InsufficientFundsError`.

### `PremiumAccount`

Премиальный счёт.

Поддерживает:

- повышенный лимит снятия;
- минимальный остаток;
- фиксированную комиссию за снятие.

Перед операцией проверяется условие:

```text
balance - amount - commission >= account_limit
```

### `InvestmentAccount`

Счёт с инвестиционным портфелем.

Портфель хранит абсолютные денежные значения:

```text
STOCKS -> 10000
BONDS  -> 5000
ETF    -> 3000
```

Свободные деньги и инвестиции учитываются отдельно.

Общая стоимость счёта:

```text
free_cash + portfolio_value
```

Методы позволяют:

- пополнять и снимать свободные средства — `deposit(amount)` / `withdraw(amount)`, как у остальных счетов;
- инвестировать свободные средства в актив — `buy_asset(asset, amount)`;
- выводить средства из актива обратно в свободный баланс — `sell_asset(asset, amount)`;
- рассчитывать распределение портфеля;
- рассчитывать ожидаемый годовой рост.

## Enum

### `Status`

Статусы:

```python
ACTIVE
FROZEN
CLOSED
BLOCKED
```

Для счетов используются прежде всего `ACTIVE`, `FROZEN` и `CLOSED`. `BLOCKED` применяется к заблокированному клиенту.

Правила для финансовых операций:

| Статус | Deposit | Withdraw |
|---|---|---|
| `ACTIVE` | Разрешён | Разрешён |
| `FROZEN` | Запрещён | Запрещён |
| `CLOSED` | Запрещён | Запрещён |

## Исключения

Проект содержит собственные исключения:

| Исключение | Назначение |
|---|---|
| `AccountFrozenError` | Операция над замороженным счётом |
| `AccountClosedError` | Операция над закрытым счётом |
| `InvalidOperationError` | Некорректная операция или входные данные |
| `InsufficientFundsError` | Недостаточно доступных средств |

`InsufficientFundsError` также используется, когда операция снятия нарушает минимальный остаток накопительного или премиального счёта.

## Клиенты

`Client` представляет владельца счетов.

Клиент содержит:

- `client_id`;
- персональную информацию;
- статус;
- множество идентификаторов счетов;
- контакты;
- возраст;
- пароль;
- количество неудачных попыток аутентификации;
- состояние блокировки.

Возраст клиента должен быть не меньше 18 лет.

Счета хранятся в `set`, поэтому проверка принадлежности счёта выполняется в среднем за `O(1)`.

## Bank

`Bank` является координатором системы.

Основные операции:

```text
add_client()
open_account()
close_account()
freeze_account()
unfreeze_account()
authenticate_client()
search_accounts()
get_total_balance()
get_clients_ranking()
```

### Аутентификация

После трёх неверных попыток входа клиент блокируется.

Неудачные попытки и подозрительные действия могут записываться в `AuditLog`.

### Проверка владельца

Перед защищённой операцией проверяется:

```python
account_id in client.accounts
```

Это предотвращает выполнение операций над чужим счётом.

### Ночное ограничение

Финансовые операции запрещены в период:

```text
00:00–05:00
```

## Transactions

`Transaction` описывает финансовую операцию.

Содержит:

- ID транзакции;
- тип;
- сумму;
- валюту;
- комиссию;
- счёт отправителя;
- счёт получателя;
- статус;
- причину ошибки;
- время создания;
- время обработки.

Для денежных значений используется `Decimal`.

### Жизненный цикл

```text
PENDING
   |
   v
PROCESSING
   |
   +----> COMPLETED
   |
   +----> FAILED
```

Отмена возможна для ожидающей транзакции:

```text
PENDING -> CANCELLED
```

Некорректные переходы между статусами запрещены.

## TransactionQueue

Очередь транзакций реализована через `heapq`.

Элемент очереди учитывает:

- время выполнения `execute_at`;
- приоритет;
- дополнительный счётчик для однозначного сравнения;
- транзакцию.

Добавление и извлечение элемента выполняются за:

```text
O(log n)
```

Отмена транзакции по ID в простой реализации требует поиска и имеет сложность `O(n)`.

## TransactionProcessor

Процессор выполняет транзакции разных типов:

- `TRANSFER`;
- `DEPOSIT`;
- `WITHDRAW`.

Также поддерживаются:

- комиссии;
- конвертация валют;
- повторные попытки;
- обработка ошибок;
- защита от повторного применения операции.

Для разных валют используется:

```text
converted_amount = amount * exchange_rate
```

Если валюты одинаковые, конвертация не выполняется.

Уже завершённая транзакция не должна повторно изменять баланс.

## AuditLog

`AuditLog` хранит события системы.

Запись содержит:

- время;
- уровень;
- действие;
- сообщение;
- необязательный `client_id`;
- необязательный `transaction_id`.

Логи можно хранить в памяти и сохранять в формате JSON Lines.

Поддерживается фильтрация по уровню, клиенту и действию.

## RiskAnalyzer

`RiskAnalyzer` рассчитывает уровень риска операции.

Используемые факторы:

| Фактор | Баллы |
|---|---:|
| Большая сумма | +2 |
| Частые операции | +2 |
| Новый счёт | +2 |
| Операция ночью | +2 |

Уровни:

```text
score < 2       -> LOW
2 <= score <= 4 -> MEDIUM
score >= 5      -> HIGH
```

### Анализ клиента

Важно: `sender` и `receiver` транзакции содержат **ID счетов**, а не ID клиентов.

Поэтому для анализа клиента используются его идентификаторы счетов:

```python
client_account_ids = client.accounts
```

Транзакция относится к клиенту, если:

```python
transaction.sender in client_account_ids
or transaction.receiver in client_account_ids
```

Результат содержит количество транзакций каждого уровня риска.

## ReportBuilder

`ReportBuilder` отвечает за формирование отчётов и визуализацию.

Поддерживаются:

```text
client_report()
bank_report()
risk_report()
transaction_statistics()
export_to_json()
export_to_csv()
save_charts()
```

### Client report

Отчёт по клиенту включает его счета, балансы и связанные транзакции.

### Bank report

Банковский отчёт содержит общую информацию о клиентах, счетах и стоимости активов.

Для `InvestmentAccount` учитывается:

```text
free_cash + portfolio_value
```

### Transaction statistics

Статистика учитывает все статусы:

```text
PENDING
PROCESSING
COMPLETED
FAILED
CANCELLED
```

### JSON

Пример:

```python
report_builder.export_to_json(
    report_builder.bank_report(),
    "reports/bank_report.json",
)
```

### CSV

Статистика в формате словаря может экспортироваться как:

```text
metric,value
total,10
pending,1
processing,0
completed,7
failed,1

```

### Charts

`save_charts()` создаёт директорию для графиков автоматически.

Могут сохраняться графики:

- балансов клиентов;
- статусов транзакций;
- движения транзакций.

## Сложность основных операций

| Операция | Временная сложность |
|---|---:|
| Создание счёта | `O(1)` |
| `deposit()` | `O(1)` |
| `withdraw()` | `O(1)` |
| `get_account_info()` | `O(1)` |
| Investment deposit | `O(1)` |
| Investment withdraw | `O(1)` |
| Portfolio distribution | `O(a)` |
| Yearly growth projection | `O(a)` |
| Add client | `O(1)` |
| Authenticate client | `O(1)` |
| Search accounts | `O(a)` |
| Total bank balance | `O(a)` |
| Client ranking | `O(c log c + a)` |
| Transaction creation | `O(1)` |
| Queue add | `O(log n)` |
| Queue pop | `O(log n)` |
| Queue cancel | `O(n)` |
| Audit filter | `O(n)` |
| Risk analysis | `O(n)` |
| Client risk analysis | `O(t)` |
| Transaction statistics | `O(n)` |
| Client report | `O(a + t)` |

Где:

```text
a = количество счетов
c = количество клиентов
n = количество транзакций или записей логов
t = количество транзакций клиента
```

## Принципы архитектуры

Проект разделяет ответственность между компонентами:

```text
AbstractAccount
      |
      +---- BankAccount
              |
              +---- SavingsAccount
              +---- PremiumAccount
              +---- InvestmentAccount

Client <----> Bank
                |
                +---- accounts
                +---- authentication
                +---- ownership
                +---- search
                +---- statistics

Transaction --> TransactionQueue --> TransactionProcessor

Transaction --> RiskAnalyzer

Operations --> AuditLog

Bank / Transactions / Risk
             |
             v
       ReportBuilder
```

Основная идея — финансовая логика находится в счетах и процессоре транзакций, управление клиентами и принадлежностью счетов — в `Bank`, аудит — в `AuditLog`, анализ рисков — в `RiskAnalyzer`, а формирование результатов — в `ReportBuilder`.
