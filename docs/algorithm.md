# Bank Account Micro Project — Алгоритм

## 1. Общая архитектура

Проект представляет собой учебную банковскую систему, состоящую из следующих основных компонентов:

* счета клиентов;
* клиенты и аутентификация;
* управление счетами через банк;
* банковские транзакции;
* очередь транзакций;
* обработка транзакций;
* аудит действий;
* анализ рисков;
* формирование отчетов;
* экспорт отчетов в JSON и CSV;
* построение графиков.

Основные сущности:

```text
Client
   |
   +---- BankAccount
   |       |
   |       +---- SavingsAccount
   |       +---- PremiumAccount
   |       +---- InvestmentAccount
   |
   +---- Transaction
            |
            +---- TransactionQueue
            +---- TransactionProcessor
```

# 3. Исключения

В проекте используются собственные исключения:

```python
class AccountFrozenError(Exception):
    pass


class AccountClosedError(Exception):
    pass


class InvalidOperationError(Exception):
    pass


class InsufficientFundsError(Exception):
    pass
```

Назначение:

* `AccountFrozenError` — операция запрещена для замороженного счета;
* `AccountClosedError` — операция запрещена для закрытого счета;
* `InvalidOperationError` — некорректная операция или входные данные;
* `InsufficientFundsError` — недостаточно средств.

# 4. AbstractAccount

`AbstractAccount` — абстрактный базовый класс для всех банковских счетов.

Класс должен наследоваться от:

```python
ABC
```

Основные поля:

```text
account_id
personal_info
_account_balance
account_status
```

Основные методы:

```python
deposit()
withdraw()
get_account_info()
```

Эти методы являются абстрактными:

```python
@abstractmethod
def deposit(...):
    pass
```

```python
@abstractmethod
def withdraw(...):
    pass
```

```python
@abstractmethod
def get_account_info(...):
    pass
```

Также базовый класс может содержать свойство:

```python
@property
def total_balance(self):
    return self._account_balance
```

Для обычных счетов общий баланс равен банковскому балансу.

`InvestmentAccount` переопределяет это свойство, поскольку его общий баланс включает инвестиционный портфель.

# 6. SavingsAccount

`SavingsAccount` наследуется от `BankAccount`.

Дополнительные параметры:

```text
minimum_balance

```

---

## Минимальный баланс

После снятия денег баланс не должен становиться меньше установленного минимального значения.

Например:

```text
Баланс: 10 000
Минимальный баланс: 3 000
Снятие: 8 000
```

После операции:

```text
10 000 - 8 000 = 2 000
```

Это меньше минимального баланса.

Поэтому необходимо выбросить:

```python
InsufficientFundsError
```

Важно: нарушение минимального остатка рассматривается как недостаток доступных средств, поэтому используется именно `InsufficientFundsError`, а не `InvalidOperationError`.

---

## Начисление процентов

Ежемесячные проценты рассчитываются:

```text
interest = balance * monthly_interest_rate
```

После этого проценты добавляются к балансу:

```text
balance = balance + interest
```

Например:

```text
Баланс = 100 000
Ставка = 0.01
```

Тогда:

```text
interest = 100 000 * 0.01 = 1 000
```

Новый баланс:

```text
101 000
```

# 7. PremiumAccount

`PremiumAccount` наследуется от `BankAccount`.

Дополнительные параметры:

```text
account_limit
withdrawal_commission
```

Тип счета:

```python
AccountType.PREMIUM
```

---

## Снятие средств

При снятии необходимо учитывать комиссию.

Условие:

```text
balance - amount - commission >= account_limit
```

Например:

```text
Баланс: 10 000
Снятие: 2 000
Комиссия: 50
Минимальный остаток: 0
```

После операции:

```text
10 000 - 2 000 - 50 = 7 950
```

Комиссия также списывается с баланса.

# 8. InvestmentAccount

`InvestmentAccount` наследуется от `BankAccount`.

Он содержит:

```text
free cash
portfolio
```

Портфель имеет структуру:

```python
portfolio: dict[AssetType, Decimal]
```

Пример:

```python
{
    AssetType.STOCKS: Decimal("50000.00"),
    AssetType.BONDS: Decimal("30000.00"),
    AssetType.ETF: Decimal("20000.00")
}
```

В портфеле хранятся **абсолютные суммы**, а не проценты.

При создании счета все поддерживаемые активы должны быть инициализированы:

```text
STOCKS -> 0.00
BONDS  -> 0.00
ETF    -> 0.00
```

---

## total_balance

Общий баланс инвестиционного счета:

```text
total_balance =
    free cash + сумма всех активов портфеля
```

Например:

```text
Свободные деньги: 10 000
Акции: 50 000
Облигации: 30 000
ETF: 20 000
```

Тогда:

```text
total_balance = 110 000
```

---

## deposit(amount) / withdraw(amount)

Обычные денежные операции со свободными средствами — с той же сигнатурой, что и у остальных счетов. `withdraw()` не может снять больше свободных денег: вложенные в портфель средства сначала нужно продать.

---

## buy_asset(asset, amount)

Метод переводит свободные денежные средства в инвестиционный портфель.

Алгоритм:

1. Проверить `AssetType`.
2. Проверить, что сумма положительная.
3. Проверить наличие достаточного количества свободных денег.
4. Уменьшить свободный баланс.
5. Увеличить баланс соответствующего актива.

Например:

```text
Свободные деньги: 100 000
STOCKS: 20 000
```

После:

```text
buy_asset(STOCKS, 30 000)
```

получаем:

```text
Свободные деньги: 70 000
STOCKS: 50 000
```

Сложность:

```text
Время: O(1)
Память: O(1)
```

---

## sell_asset(asset, amount)

Метод переводит деньги из инвестиционного портфеля обратно в свободные средства.

Алгоритм:

1. Проверить `AssetType`.
2. Проверить положительность суммы.
3. Проверить достаточность средств в выбранном активе.
4. Уменьшить стоимость актива.
5. Увеличить свободный баланс.

Сложность:

```text
Время: O(1)
Память: O(1)
```

---

## portfolio_distribution()

Метод возвращает распределение инвестиционного портфеля в процентах.

Важно:

**Свободные деньги не учитываются в распределении.**

Например:

```text
STOCKS = 50 000
BONDS  = 30 000
ETF    = 20 000
```

Общая сумма портфеля:

```text
100 000
```

Распределение:

```text
STOCKS = 50%
BONDS  = 30%
ETF    = 20%
```

Сложность:

```text
Время: O(a)
Память: O(a)
```

где `a` — количество активов.

---

## project_yearly_growth(growth_rates)

Метод рассчитывает предполагаемый рост портфеля.

Пример:

```python
growth_rates = {
    AssetType.STOCKS: Decimal("0.10"),
    AssetType.BONDS: Decimal("0.05"),
    AssetType.ETF: Decimal("0.08")
}
```

Для каждого актива:

```text
growth = amount * growth_rate
```

Метод **не должен изменять реальный баланс**.

Он только рассчитывает ожидаемое значение.

Сложность:

```text
Время: O(a)
Память: O(1)
```

# 10. Аутентификация клиента

Клиент должен иметь пароль.

При неправильном пароле увеличивается счетчик неудачных попыток:

```text
failed_attempts += 1
```

После трех неправильных попыток клиент блокируется.

```text
failed_attempts >= 3
```

После блокировки дальнейшая аутентификация невозможна.

Необходимо также фиксировать подозрительные действия в `AuditLog`.

# 21. get_clients_ranking()

Формирует список клиентов, отсортированный по общему балансу.

Для каждого клиента необходимо учитывать:

```text
все его банковские счета
+
инвестиционные портфели
```

Алгоритм:

1. Рассчитать общий баланс каждого клиента.
2. Отсортировать клиентов по балансу.

Сложность:

```text
Время: O(c log c + a)
Память: O(c)
```

где:

```text
c — количество клиентов
a — количество счетов
```

# 23. Transaction lifecycle

Начальный статус:

```text
PENDING
```

После начала обработки:

```text
PROCESSING
```

Результат:

```text
COMPLETED
```

или:

```text
FAILED
```

Транзакцию в состоянии `PENDING` также можно отменить:

```text
PENDING -> CANCELLED
```

Нельзя повторно выполнить уже завершенную транзакцию.

---

# 24. TransactionQueue

Очередь транзакций должна использовать:

```python
heapq
```

Каждая задача содержит:

```text
execute_at
priority
counter
transaction
```

Очередь должна учитывать:

1. время выполнения;
2. приоритет;
3. порядковый номер для стабильного порядка при одинаковых значениях.

---

## Приоритет

Если большее числовое значение означает более высокий приоритет, при добавлении в heap необходимо использовать:

```python
-priority
```

Например:

```text
priority = 10
```

должен обрабатываться раньше:

```text
priority = 5
```

---

## add()

Добавляет транзакцию в очередь.

Сложность:

```text
Время: O(log n)
Память: O(1)
```

---

## pop()

Извлекает следующую транзакцию.

Транзакция может быть извлечена только если:

```text
execute_at <= current_time
```

Сложность:

```text
Время: O(log n)
Память: O(1)
```

---

## cancel()

Отмена транзакции по ID.

Поскольку `heapq` не предоставляет эффективного поиска произвольного элемента по ID, необходимо выполнить линейный поиск.

Сложность:

```text
Время: O(n)
Память: O(1)
```

---

# 25. TransactionProcessor

`TransactionProcessor` отвечает за фактическое выполнение транзакций.

Поддерживаются:

```text
TRANSFER
DEPOSIT
WITHDRAW
```

Общий алгоритм:

1. Проверить статус.
2. Перевести транзакцию в `PROCESSING`.
3. Выполнить финансовую операцию.
4. Учесть комиссию.
5. При необходимости выполнить конвертацию валют.
6. Перевести транзакцию в `COMPLETED`.
7. При ошибке перевести в `FAILED`.
8. Сохранить причину ошибки.

---

# 26. Защита от повторного выполнения

Завершенная транзакция не должна применяться повторно.

Перед выполнением необходимо проверить:

```text
transaction.status
```

Если:

```text
COMPLETED
```

то повторное списание или зачисление выполнять нельзя.

Это предотвращает двойное изменение баланса.

# 27. Комиссии

Необходимо различать:

### Комиссию перевода

Комиссия, связанная с самой транзакцией.

### Комиссию PremiumAccount

Комиссия, которую Premium-счет взимает за снятие.

Эти комиссии не должны случайно применяться дважды.

Например, если `PremiumAccount.withdraw()` уже списал комиссию:

```text
withdrawal_commission
```

то `TransactionProcessor` не должен повторно списывать ту же самую комиссию как часть операции.

# 28. Повторные попытки

Для транзакций, завершившихся ошибкой, может использоваться механизм retry.

Алгоритм:

1. Выполнить транзакцию.
2. Если произошла временная ошибка — увеличить количество попыток.
3. Если количество попыток не превышает лимит — повторить.
4. После превышения лимита установить:

```text
FAILED
```

Каждая транзакция должна применяться к балансу не более одного раза.

# 29. Конвертация валют

Конвертация выполняется по формуле:

```text

```

Например:

```text

курс = 90 RUB/USD
```

Результат:

```text
9 000 RUB
```

Если исходная и целевая валюты совпадают, конвертация не требуется.

Сложность:

```text
Время: O(1)
Память: O(1)
```

# 44. Общие требования к реализации

При реализации необходимо соблюдать следующие правила:

1. Для денежных значений использовать `Decimal`, а не `float`.
2. Для идентификаторов использовать UUID.
3. Для фиксированных наборов значений использовать `Enum`.
4. Использовать `ABC` и `abstractmethod` для абстрактного счета.
5. Не изменять баланс при расчете прогнозного роста инвестиционного портфеля.
6. Учитывать инвестиционный портфель при расчете общего баланса.
7. Не позволять выполнять операции над чужими счетами.
8. Не позволять проводить финансовые операции по закрытым и замороженным счетам.
9. Не выполнять финансовые операции с 00:00 до 05:00.
10. Не блокировать аутентификацию в ночное время.
11. После трех неудачных попыток аутентификации блокировать клиента.
12. Логировать важные и подозрительные действия.
13. Не применять одну транзакцию дважды.
14. Разделять комиссии транзакции и комиссии PremiumAccount.
15. Для очереди использовать `heapq`.
16. Учитывать приоритет и время выполнения транзакции.
17. Статистику транзакций возвращать в виде `dict`.
18. JSON и CSV сохранять с автоматическим созданием необходимых директорий.
19. При формировании клиентских отчетов учитывать только транзакции его счетов.
20. Код должен соответствовать указанным оценкам сложности алгоритмов.
